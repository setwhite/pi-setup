# 审计流程

## 前置条件

- 独立会话：在未参与编写的新会话中运行。
- 只读：不碰 `docs/todos/` 与 git 已跟踪文件；唯一写入是本次报告（`docs/audit/`）。

## Step 1 — 准备材料

1. 在 `docs/todos/` 找 `[~]` 的任务（`rg -l '^- \[~\]' docs/todos/`），取它的验收标准。
2. 检查 Git 状态，确认改动范围。

完成标准：明确改动范围与验收标准。

## Step 2 — Spec 轴：逐条核对 AC

1. 逐条跑 AC 对应的自动化检查，本会话自己跑；文件里写的、别人报告的都不算证据。
2. 每条 AC 给一个结论：达成 / 未达成 / 无法判定（没有可跑的检查，或检查与 AC 说的不是一件事）。
3. 最后跑一次全套 E2E。

完成标准：每条 AC 都有结论和证据。

## Step 3 — Standards 轴：对照规范

1. 对照 `AGENTS.md` 与仓库里的规范文件。
2. 工具已经能查的（lint、类型、格式）不重复报。
3. 仓库没写规范处用 smell 清单兜底（`references/smells.md`）：只是判断线索不是违规认定，与仓库规范冲突时以仓库为准。

完成标准：每条发现都能指到依据（AGENTS 条款或 smell 名）。

## Step 4 — 输出

按 `references/report-format.md` 落盘 `docs/audit/T<NN>-YYYY-MM-DD.md`，落盘后在会话里重述同一份内容。

- 两轴分开写：一根轴过、另一根轴挂是两回事。
- 只给意见，不给实现方案，是否返工由用户决定。

完成标准：判定与发现已落盘，意见精确定位到文件，未修改任何已跟踪文件。
