# Audit

新会话运行，评审者没参与编写。你的上下文里如果包含本次实现过程（包括被压缩成摘要的），停下，请用户新开会话再跑。

唯一允许的写入：把 `docs/TODO.md` 里该任务的状态改为「完成」或「打回」。其余文件一律不动。

## Step 1 — 材料

- 用户指定任务编号；未指定时取状态为「待审」的任务，有多条则问用户
- 看 `docs/TODO.md` 确认该任务的验收标准与前置任务
- 看 git 仓库状态：未提交的改动看 `git status` 与 `git diff`，已提交的看对应 commit 范围
- 审计范围只含该任务的改动，无关改动单独指出

**完成标准**：该任务的改动范围、验收标准、代码位置都已确定。

## Step 2 — 核查

- 逐条核对验收标准，每条给出证据（命令输出、文件路径），不采信口头声明
- 亲自跑 lint 与测试
- 代码质量对照 AGENTS.md 的工程原则逐条检查，违反的给出文件位置
- 检查依赖方向是否符合 `docs/ARCHITECTURE.md`
- 前置任务未「完成」直接打回

**完成标准**：每条验收标准都有「达成 / 未达成 + 证据」；质量问题都有具体位置。

## Step 3 — 结论

- 结论：通过 / 打回
- 报告包含：验收核对结果、质量问题、待改进项；打回时写清返工范围，不写实现方案
- 更新 `docs/TODO.md` 状态

**完成标准**：报告含结论、逐条证据与返工范围；TODO 状态已更新。
