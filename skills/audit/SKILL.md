# Audit

新会话运行，评审者没参与编写；能看到写代码过程的会话不算，停下说明。只报不改。

## Step 1 — 材料

- 基准点：用户指定，或 `git merge-base main HEAD`。
- 验收标准与证据：`docs/TODO.md` 各任务的验收标准、勾选、commit / diff；没有就问用户要，拿不到就标「无验收标准」。

**完成标准**：基准点能解析且 `git diff <基准点>` 非空；验收标准与证据到手，或「无验收标准」已标明。

## Step 2 — 机器门槛

重跑全量 typecheck、lint、test，不采信勾选结论；有 PR 查 `gh pr checks`。

**完成标准**：每项检查有结果——通过、失败项与原始输出、或环境缺口与已试手段。

## Step 3 — 两轴核查

两轴分开报。只认证据，拿不准标未验证。每条问题给文件与行、命令或输出片段。

- Spec：逐条验收标准标通过 / 未通过 / 未验证；另记缺失、超范围、实现存疑。
- Standards：
  - 阻塞：违反 AGENTS.md；按技术分层而非业务模块组织；`docs/ARCHITECTURE.md` 与实际不符（模块清单、README 链接、依赖方向）；新模块必备文件与代码风格按 [coding 的「模块」「代码风格」两节](../coding/SKILL.md) 逐条检查，缺失或超标即阻塞。
  - 非阻塞：坏味道，标「可能 X」，只列影响大的。
  - lint 与 typecheck 已报的跳过。

**完成标准**：每条验收标准有结论；每条问题有证据位置。

## Step 4 — 结论

Spec 全通过且无阻塞项就建议通过，否则列阻断项建议打回；打回内容写到编写方能直接执行。

**完成标准**：用户已裁定；打回任务在 `docs/TODO.md` 标「打回」。
