# 审计流程

**独立性约束**：必须在未参与编写的新会话中运行。
**只读原则**：严禁修改 `docs/TODO.md` 或任何仓库文件。

## Step 1 — 准备材料
1. 读取 `docs/TODO.md` 确认验收标准与证据指针。
2. 检查 Git 状态：用 `git status` 与 `git diff` 确认改动范围。

**完成标准**：明确改动范围与验收标准。

## Step 2 — 深度核查
1. **验收核对**：逐条核对验收标准。证据仅认当前会话运行输出。
2. **质量检查**：亲自运行 `uv run ruff check`、`uv run basedpyright` 与测试。
3. **规范对照**：对照 `AGENTS.md` 逐条检查，违规项必须精准引用条款与文件位置。

**完成标准**：每条验收标准得出「达成 / 未达成 + 证据」，质量问题精确定位。

## Step 3 — 输出意见
- 格式：`文件位置 + 观察事实 + 依据（AGENTS.md 条款或验收标准）`。
- 不打分、不定性、不提供实现方案，是否返工由用户裁决（状态仅在用户确认勾选时更改）。

**完成标准**：意见精确定位到文件，未做任何文件修改。
