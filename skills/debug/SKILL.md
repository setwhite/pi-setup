# Debug（诊断循环）

轻的 Bug 直接答，不进循环：一眼可见的笔误、类型报错、没装的依赖。有 `docs/GLOSSARY.md` 与相关 ADR 就先读，建立心智模型。

## 脱敏

本 skill 会展示命令、输出、抓包。先脱敏：密钥、token、cookie 写成 `<REDACTED>`。凭据走环境变量，不进展示内容。带 auth header 的日志只引有信号的那几行。脱敏后不够判断就说出来，向用户要。

## Step 1 — 造回路

**价值全在这一步。** 有能在**这个** Bug 上变红的 pass/fail 信号，后面都是机械活。没有这个信号，盯代码无用。

### 手段

大致按此序：

1. 失败的测试：选能触达 Bug 的那层 seam（unit / integration / e2e）
2. 用 curl / HTTP 脚本打本地 dev server
3. 用 CLI 喂一个 fixture，把 stdout 与已知正确快照 diff
4. 回放抓包：把真实请求 / payload / 事件日志写入文件，单独喂进代码路径
5. 一次性 harness：用最小子集（一个服务、mock 依赖）单次调用走 Bug 路径
6. 属性 / fuzz：用随机输入运行 1000 次，找失败模式
7. bisect harness：在两个已知状态间自动「起 X、检查、重复」，可交 `git bisect run`
8. 差分：同一输入运行新旧两版或两套配置，diff 输出
9. 人在回路（最后手段）：只能人点时用脚本驱动人，输出仍要回传

### 打磨

- 更快：缓存 setup，缩小测试范围
- 信号更尖：断用户那个症状，不是「没崩」
- 更确定：钉时间、种 RNG、隔离文件系统、冻网络

30 秒还会闪的回路约等于没有。2 秒且确定的才叫 tight。

### 闪烁的 Bug

目标不是干净复现。目标是把复现率抬到可调的档位：循环触发 100 次、并行、加压、卡时间窗。

### 真造不出来

停止并说清楚。列出你试过的。向用户要 (a) 能复现的环境 (b) 脱敏后的抓包、日志或堆栈 (c) 允许加临时埋点。

**完成条件**：能点出**一条命令**（脚本路径、测试调用、curl）。它已经运行过至少一次，调用与输出（脱敏后）已贴出。且它满足：

- [ ] 能变红：走真实 Bug 路径，断言**用户说的那个症状**，不是「运行起来没报错」
- [ ] 确定：每次运行结论一样（闪烁 Bug 按「闪烁的 Bug」的复现率算）
- [ ] 快：秒级
- [ ] 可无人运行

**没这条命令就不许进 Step 2。** 发现自己开始读代码建理论，停止：这正是本 skill 要拦的失败。

## Step 2 — 复现 + 最小化

运行到红，确认三件事。第一，这个失败模式是用户描述的那个，不是附近另一个。第二，多运行几次都复现。第三，症状（错误信息、错输出、慢了多少秒）已留存，供 Step 6 验收。

最小化：一次删除一个元素（输入、调用方、配置、数据、步骤）。每删除一个就重新运行。标准是：删除任何一个元素都会变绿。

## Step 3 — 列假设

先写 3–5 条并排序，再测任何一条。只写一条，你会只测第一条假设。每条可证伪，并写出预测：「如果 X 是原因，改 Y 让它消失 / 改 Z 让它更糟」。写不出预测的假设要删除，或写得更具体。

测之前把清单给用户看。他们常有领域知识能一秒重排（「我们刚发过 #3 的改动」），或已知排除过哪些。用户不在就按自己的排序继续，不要停止。

## Step 4 — 埋点

每个探针必须对应 Step 3 的某条预测。一次只改一个变量。优先级：调试器 / REPL（一个断点胜过十行 log）> 在能区分假设的边界打靶向 log。「全打 log 再 grep」不算。

每条调试 log 带唯一前缀如 `[DEBUG-a4f2]`。收工时用一条 grep 清干净。没前缀的 log 会活下来。

性能回归另走一条路：log 通常是错的。先立基线（计时 harness、profiler、查询计划），再 bisect。先量，后修。

## Step 5 — 修 + 回归测试

先写回归测试。测试要有正确的 seam：走真实 Bug 模式在调用点的样子。只有浅 seam 时不写（该由多调用方驱动却写成单调用方测试、单测复不出触发链）。浅测试只会给假信心。

没有正确 seam 本身就是结论：记下来，架构挡住了这个 Bug 的锁定。不要用浅测试代替。

有 seam 就按序做。先把最小复现改成失败测试。再确认它红。若红是改代码或夹具逼出来的，先 diff 一份干净副本，证明改动真的落地。然后修。看它绿。最后用原始未最小化的场景重新运行 Step 1 回路。

## Step 6 — 收工

- [ ] 原始复现不再复现（重新运行 Step 1 回路）
- [ ] 回归测试通过，或已记下缺 seam
- [ ] `[DEBUG-` 埋点全清（grep 一遍）
- [ ] 一次性原型删除
- [ ] 命中的那条假设写入 commit / PR 信息，供下一个调试的人参考
