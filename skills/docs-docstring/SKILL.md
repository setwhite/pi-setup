# 注释与 Docstring

默认不写。代码说清 what，注释只说代码说不出的 why。

## 判据

删掉它，下一个人会不会踩坑或猜错？会才写。不会就是噪音，删。

值得写的只有三种：

- **不变量** —— 必须保持的顺序、幂等、不可重入、并发假设
- **绕坑的原因** —— 外部系统的怪癖、某版本的行为、看起来多余却删不掉的那行
- **类型写不出的契约** —— 前提条件、副作用、会抛的异常、生命周期与归属

不写：代码已经表达的 what、how、变更历史、TODO（TODO 归 `docs/todos/`）。

## Docstring

只补类型写不出的部分。参数与返回值交给类型标注，不复述；例外是单位、取值范围、null 的含义这类类型表达不了的。

公开入口写，其余函数除非命中上面三条之一否则不写。格式随仓库既有风格（Google、NumPy、JSDoc 或语言默认），没有先例就选该语言生态的主流。

**Completion criterion**：没有一条注释在复述代码；每条都能回答「删了会怎样」；公开入口要么写清契约，要么明确不需要。
