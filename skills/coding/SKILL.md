# Coding

通用约束（语言、工程原则、需要确认才能做的操作）见 agent 的 `AGENTS.md`，这里只写开发流程。

## Step 1 — 领任务

取 `docs/TODO.md` 里一条「未开始」或「打回」的任务；没有 `docs/TODO.md` 就问用户要范围。
先读三样：验收标准、模块 README（契约）、依赖任务的产出。需求或取舍不明时先读代码，再问用户。

**完成标准**：任务、验收标准、契约都明确，依赖已完成。

## Step 2 — 红/绿 TDD

先写测试并跑一次，确认它真的失败（红）；再写实现，跑到通过（绿）。
断言落在模块公共入口上；HTTP、sleep、时钟这类 I/O 接缝可以换成假实现。

**完成标准**：有红、有绿的运行记录；测试不联网、不真等。

## Step 3 — 检查与证据

跑项目定义的全部检查（Python 项目：`uv run pytest`、`uv run ruff check`、`uv run basedpyright`），全绿。
再看契约：实现和 README 对不上，改 README 再收工。
在 `docs/TODO.md` 勾选验收、写证据：改了哪些文件、实测数字、检查结果。

**完成标准**：检查全绿、TODO 已更新，然后停下等 review；commit / push 需要用户确认。

## 模块与布局

新模块一次建齐 README.md（契约）、实现文件、公共入口、类型、测试。
布局照项目既有约定（项目 ARCHITECTURE 或相邻模块的写法）；项目没约定时，Python 用 `<module>/<module>.py` 放实现、`__init__.py` 只重导出（`from .<module> import name` + `__all__`）。
要改结构（文件布局、目录划分、公共 API 面）时停下问用户。

单文件超 300 行就拆文件，不申请例外。

## 代码风格

- 函数体 ≤ 50 行，嵌套 ≤ 3 层，单文件 ≤ 300 行（按 `wc -l`，含注释与空行）
- 位置参数 ≤ 3 个（`self` / `cls` 不计，`*` 之后的关键字参数不计）；超了改成关键字参数或收进数据类
- 魔法数字用命名常量（0、1、-1 等公认语义除外）
- 函数签名、类属性、数据类字段完整类型标注
- 修改/新增代码保持周边风格
- 文档只做索引与事实陈述，信息唯一，不用文字复述代码逻辑
