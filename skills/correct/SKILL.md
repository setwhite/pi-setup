# 失误固化

把仓库里反复出现的同类失误变成机器能拦住的硬约束，减少口头规则。

## 1. 归类失误

读近期 `git log`、revert、review 评论与绕坑注释，按根因归纳失误类别；至少出现 2 次才立项。

## 2. 按最高有效层级修复

优先选排在前面的层级，上层能拦住就不靠下层：

1. Architecture：给每份状态唯一归属与唯一写法，隐藏内部文件让错误导入直接失败，删掉容易被抄走的旧写法和死代码。
2. Types & Lint：用类型让非法状态写不出来；编译拦不住的加 lint 或 CI 检查，报错信息直接指出正确替代项（存量已多时只拦增量）。
3. Behavior Test：补或修只在行为破坏时失败、内部重构不误报的测试。
4. Prose：仅用于机器判不了的判断类约定。

## 3. 落地与瘦身

- 挑最高频的 1 到 3 类落地，每类单独整理改动。
- Prove the Check：用一次真实历史错误证明新检查确实会失败；本地与 CI 跑同一条命令。
- Prune Prose：规则一旦被上层机制强制执行，立刻从 `AGENTS.md` 或文档里删掉对应口头约定。

## 汇报骨架

```md
- <失误类别>（证据：<commit/文件>）
  - 选定层级：<Architecture / Types & Lint / Behavior Test / Prose>（未选更高层原因）
  - 改动与拦截验证：<改动摘要 + 旧错实跑拦截结果>
  - 已删口头规则：<路径或无>
```
