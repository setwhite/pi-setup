# 文章写作

两个阶段：explore 把能写的东西摊开，exploit 定结构并逐段成形，可分两个会话做。碎片文件与文章文件是两个文件；exploit 只读碎片，不改它。

## explore：收碎片

grill 用户，问到他开始冒句子为止。碎片一出现就追加进碎片文件，第一条从他最初的表述里取。

- 开头只放一个 H1 暂定标题，不要 TOC、日期、元信息。
- 碎片之间用 `---` 分隔。
- 标准是「这是一段好文字吗」，不是「冷读者能看懂吗」；作者自己看得懂就够。
- 碎片可以是：不知放哪的一句话、断言加一行理由、小场景、半成品比喻、引文、一串凭感觉放的观察。
- 最值钱的碎片是 leading word：能命名整个想法的紧凑词或比喻（tracer bullets、fog of war）。话题反复绕回某个念头时，推用户造词。

## exploit：成形

读完整份碎片（从磁盘读，不靠记忆），然后：

1. 定前提：和用户敲定读者带着什么知识进来。
2. 给 2–3 个候选开头，每个通向不同的论点，让用户挑或拼；选定开头决定后文必须做什么。
3. 逐段长：每段问「读者接下来需要听到什么」，从碎片里取材料填；段的形式（段落、列表、表格、引用、代码）要说得出理由。
4. 写完一段立刻追加进文章文件，不批量，让用户看着文章成形。
5. 重复 3–4 直到用户说停。

## grounding

概念用到之前必须已经 grounded：读者要么本来就懂，要么前面段落已建立；否则读者掉线——这是唯一的死线。

概念不是词：读者可以没有术语却仍然缺那个想法。有名字的概念，落地时让想法和名字一起到位。

文章不是项目文档，不进 `docs/`；问用户一次存哪，记住。
