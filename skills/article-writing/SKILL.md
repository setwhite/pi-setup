# 文章写作

## 风格

- 面向有基础的技术读者，不解释基础语法，不科普行业常识
- 禁止感叹号、反问句、破折号、emoji
- 每段 ≤ 5 句，超了拆成列表或表格
- 代码块行内注释说关键步骤，不另建参数说明表
- 三段文字能说清的，不加图
- 先给结论，再解释；避免「首先…其次…最后…我们来试试」的教程体

## 结构

```
标题（一句话说清解决什么问题，≤ 25 字）

撰写日期：YYYY 年 M 月 D 日

一、省流

≤ 3 句，直接给结论或核心观点，不铺垫，不设问。

二、正文

标题编号：一、 → （一） → 3. → （4）
模块按需组合，不必全出现：
- 问题区 —— 解决什么问题、为什么值得写
- 原理区 —— 机制解释，配合代码或图
- 实践区 —— 可复现的步骤、代码示例
- 对比区 —— 方案/工具/版本对比，优先表格
- 踩坑区 —— 错误及原因，不罗列显而易见的注意事项

三、总结

≤ 3 句，回顾核心结论，不复述正文小节标题。

参考链接

正文引用的全部外部来源，每条带链接文本（非裸 URL）；未引用的不列。
```

## Step 1 — 搭骨架

- 只到结构层：标题、省流方向、模块清单、每模块目标字数、待搜索清单
- 发给用户确认后再继续

**完成标准**：骨架要素齐备并获用户确认。

## Step 2 — 搜索

- 并行搜多组关键词，信息不足就扩词再搜一轮
- 官方文档、规范、性能数字、版本及 API 变更、第三方库用法必须核实
- 来源矛盾时官方文档优先，官方过时则采信源码

**完成标准**：待搜索清单逐项有来源链接；必须核实项来源可查。

## Step 3 — 成文

- 按确认后的大纲展开

**完成标准**：单文件已写入当前工作目录，命名 `YYYY-MM-DD-标题.md`（标题取自主题，中文）。
