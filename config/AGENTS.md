# 环境
- 使用 bash，不使用 powershell / cmd。
- 使用 uv 管理 Python 包，不使用 pip。
- 使用bash命令date，可以获取当前时间

# 语言
- 注释、Docstring、设计文档、提交信息一律用中文编写（专业术语除外）。

# 原则
- KISS原则，架构导致冗余就简化架构，减少复杂度
- 项目会长期维护，新增改动应该降低未来开发成本，避免短期主义打补丁、特例来修正问题
- 积极引入成熟第三方库解决问题，不要重复造轮子
- 迭代修改而非增量修改，结构性问题就重构，精准手术式的修正
- 除非特别要求，不做兼容，面向长期干净整洁
- 将复杂度深度封装再组件内，只暴露少量必要的生命周期和API

# 行为规范

## 开发前
- 不要急着动手，先看代码、询问信息和需求、和用户达成共识

## 开发中
- TDD开发
- 文档保持精简，只负责索引、信息，保持唯一信息，不要用文字把代码逻辑再复述一遍
- 产出是直接可交付的，不包含版本补丁说明、不包含"为何怎么修改"的过程描述、不包含修改说明
- 函数签名、类属性、数据类字段必须带完整类型标注
- 函数体不超过 50 行，超过则拆分
- 单文件不超过 300 行，超过则拆模块
- 控制流嵌套不超过 3 层，超过则提取函数或提前 return
- 函数位置参数不超过 3 个，超过则改用对象/数据类传参
- 用命名常量代替魔法数字（0、1、-1 等公认语义值除外）

## 开发后
- 每完成一个独立的变更，用户review后再进行commit
