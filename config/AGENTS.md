# Communication
- 极简表达：用自然、地道的中文。术语保留英文。注释、Docstring 和 Commit Message 强制用中文。
- 结论先行：直接给结果/代码。有更优的极简方案时，一句话带过即可。
- 事实驱动：引用原文（附文件路径）代替转述。表达观点必须附带代码示例或数据。
- 闭环收尾：若需用户介入，提供耗时 <2 分钟的明确「下一步」指令。

# Execution (严格按 1->7 降级处理)
1. 提问截断：需求模糊或面临重大取舍时，停止猜测，直接提问。
2. 零代码：优先用现有配置、系统命令或手动操作解决。
3. 降维复用：优先清理废弃代码，或复用现有组件。
4. 原生优先：强制用平台标准库和现有依赖。密码学、协议解析等复杂逻辑必须用成熟库。
5. 极小化改动：只做满足当前需求的最少改动，并注释影响范围。
   - 直击根因，严禁 Hardcode、吞异常或临时补丁。
   - 拒绝防御性过度设计，无当前明确用途的 API、Hook 或依赖一律不加。
6. Rule of Three：同一逻辑重复出现 3 次以上，才允许提取新抽象。
7. 架构重构：若因架构导致严重冗余，先给重构方案，获批后再改。

# Engineering & Debugging
- 黑盒封装：复杂度锁在组件内，对外仅暴露极简 API 与必要生命周期。
- Todo 驱动：预计 >3 步的任务，先用 Todo 工具。每次执行仅限 1 步开发 + 单测。Todo 都完成后清理。
- 证据调试：遇 Bug 必须先加 Log/Print 或查堆栈验证假设，绝对禁止「盲猜试错」。
- 3 次熔断：同一报错连续失败 3 次必须强制停机。并汇报：当前状态、失败原因、核心日志、你的可疑假设。

# Output
- 纯粹交付：直接给完整代码或精确 diff 块。禁止啰嗦修改心路历程、版本号或补丁说明。
- SSOT 原则：代码库是唯一事实来源，文档只写事实与索引，信息不冗余。严禁把代码逻辑翻译成自然语言。
- 省 Token 读文件：探查大文件优先用 `head`/`tail`/`rg` 看局部，禁止一次性读取 >500 行非必要代码。

# Confirmation
未经同意严禁执行：
1. 危险 Git：commit, push, 建分支, 改写历史 (amend/rebase/reset)。
2. 基建变更：加生产依赖, 改 DB schema/migration, 改 CI 配置。
3. 破坏性写：删除或覆盖非当前会话创建的文件。

# Tooling
- Python：用 `uv` (如 `uv add`/`uv run`)。禁用 `pip` 和直接运行 `python`。
- Python QA：Lint 用 `ruff`，类型检查用 `basedpyright`。
- Node：用 `pnpm`。禁用 `npm`/`yarn`。
- Shell：用 `bash`。禁用 `powershell`/`cmd`。
- 搜索：内容用 `rg`，文件名用 `fd`。禁用 `grep`/`find`。
- GitHub：PR/Issue 操作强制用 `gh` CLI。
- 时间：需精准时间先跑 `date`。
